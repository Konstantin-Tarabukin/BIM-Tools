### Этап 8.7 — GitHub Releases

Правила выбора релиза:

* `draft = true` → релиз игнорируется;
* `prerelease = true` → релиз игнорируется;
* только стабильные Releases участвуют в выборе;
* среди подходящих стабильных релизов выбирается версия с максимальным номером;
* версия пакета для фактической установки дополнительно проверяется через `UpdateInfo.json`.

Важно:

суффиксы вроде `-test`, `-beta`, `-alpha` сами по себе не являются
источником определения стабильности. Решение принимает статус
GitHub Release `prerelease`.

Протестировано:

* stable Release `v0.4.4` выбирается;
* Release с `prerelease = true` игнорируется;
* draft Release игнорируется;
* Release `v0.4.4-test` с флагом `prerelease = true` игнорируется;
* тот же тег без `prerelease` не исключается только из-за суффикса;
* выбирается максимальная версия среди стабильных Releases;
* ZIP не используется как источник версии релиза;
* версия фактического пакета проверяется через `UpdateInfo.json`.

Также реализована дополнительная защита от ошибочного ZIP:

```text
GitHub Release → загрузка ZIP → UpdateInfo.json → проверка версии
```

Поэтому Release с версией `0.4.4`, содержащий ZIP с `UpdateInfo.json`
версии `0.4.3`, не проходит проверку пакета.

Осталось:

* [ ] формально зафиксировать production-соглашение по именованию stable tags;
* [ ] проверить несколько последовательных production-обновлений;
* [ ] проверить несколько установленных версий Revit.

Статус: реализован и экспериментально проверен; требуется только финальная production-проверка.
