Архитектурное решение №1

Источник истины для журнала — сама модель Revit.

Каждый RVT хранит собственный журнал изменений в Extensible Storage.

АР.rvt
    └── Journal

ОВ.rvt
    └── Journal

ВК.rvt
    └── Journal

Преимущества:

нет конфликтов записи;
журнал всегда путешествует вместе с моделью;
не нужна сеть для сохранения записи;
резервные копии RVT автоматически содержат журнал.
Архитектурное решение №2

Окно журнала показывает объединение журналов.

То есть пользователь видит не один журнал, а результат объединения.

Например:

─────────────────────────────
АР
    • запись 1
    • запись 2

ОВ
    • запись 3

ВК
    • запись 4
─────────────────────────────

или даже общий список с колонкой Источник:

Источник	Автор	Дата	Описание
АР	Иванов	...	...
ОВ	Петров	...	...

Мне второй вариант нравится больше — его легче фильтровать и сортировать.

Архитектурное решение №3

Если связь выгружена — журнал этой модели временно недоступен.

Это ожидаемое поведение.

Плагин может показать небольшое уведомление:

Журнал модели «ОВ» недоступен — связь не загружена.

Это честнее, чем пытаться показывать устаревшие данные.

Архитектурное решение №4

Если позже появится необходимость видеть изменения даже при выгруженных связях, мы добавим слой синхронизации, а не заменим хранилище.

То есть:

UI

↓

JournalService

↓

Extensible Storage

останется без изменений.

Добавится только дополнительный механизм обмена.
